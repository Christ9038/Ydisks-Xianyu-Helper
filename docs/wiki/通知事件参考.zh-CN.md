# 通知事件参考

[English](Notification-Events) | 中文

本页说明“通知设置”页面里每个通知渠道需要填写什么、可以订阅哪些事件、事件在什么情况下触发，以及通知如何投递和重试。操作步骤见[AI、通知与运维](AI、通知与运维.zh-CN)。

## 事件类别

渠道的“通知内容”不选择任何事件表示接收全部事件；选择后只接收勾选的类别。通知只会发给**已绑定到该账号**（账号管理 → 编辑 → 通知渠道绑定）且**已启用**的渠道。

| 界面名称 | 编码 | 触发条件 |
| --- | --- | --- |
| 掉线通知 | `account_offline` | 账号消息连接中断、掉线、登录凭证过期或自动恢复失败（连续失败达到上限时为“严重”级别）；同一次掉线只通知一次。 |
| 恢复通知 | `account_recovered` | 账号重新连接闲鱼消息服务并恢复在线，正文包含掉线开始时间。 |
| 禁用通知 | `account_disabled` | 界面说明：连续失败、账密错误等导致账号停用。 |
| 风控验证 | `security_verification` | 闲鱼要求滑块、人脸、扫码等安全验证。 |
| 拍下改价 | `automation_order_created` | “拍下改价”自动化任务进入成功或失败终态。 |
| 付款发货 | `automation_order_paid` | “付款发货”自动化任务进入成功或失败终态（砍价订单的付款后发货同属此类）。 |
| 评价赠品 | `automation_buyer_reviewed` | “评价赠品”自动化任务进入成功或失败终态。 |
| 求评价 | `automation_review_missing_timeout` | “求评价”自动化任务进入成功或失败终态。 |
| 手动发货结果 | `manual_delivery_result` | 在订单页手动完整发货或手动确认发货的结果；标题为“【手动发货】成功/失败”。 |
| 需要人工处理 | `manual_intervention_required` | 自动化因结果不确定、状态缺失或无法安全续跑而停止，需要检查订单；级别为“严重”。 |
| 续期通知 | `token_renewal` | API 自动续期连续失败 3 次时通知一次。 |
| 系统错误 | `system_error` | 界面说明：后台任务或系统级异常。 |

说明：

- 自动化任务的运行进入“需人工核对”状态时，发出的是“需要人工处理”通知；为兼容旧订阅，只订阅了对应自动化类别（例如“付款发货”）的渠道同样会收到。
- 旧版统一的“交易通知”（`delivery_result`）订阅仍然有效，会同时放行四类自动化事件、“手动发货结果”和“需要人工处理”；在界面编辑该渠道时会自动展开为这六项。
- 通知首行固定为“【类型】成功/失败”（没有成败语义的事件没有后缀），手机推送预览只显示首行也能看出事件；随后是级别（提示/警告/严重）、账号、时间和事件明细。

## 渠道类型与填写项

| 渠道 | 必填 | 可选 |
| --- | --- | --- |
| Bark | Bark 服务器（如 `https://api.day.app`）、Device Key | 标题（默认取通知首行）、铃声（默认 `default`）、分组（默认 `xianyu`） |
| 钉钉机器人 | Webhook URL | 加签密钥（安全设置勾选“加签”后生成，`SEC` 开头） |
| 飞书机器人 | Webhook URL | 签名校验密钥（安全设置选“签名校验”后生成） |
| 企业微信机器人 | Webhook URL | — |
| Telegram | Bot Token、Chat ID（群为 `-100…`，私聊为你的用户 ID） | — |
| 邮件 | 收件邮箱；发件使用系统 SMTP，或开启“使用独立 SMTP”后填写整套配置 | 独立 SMTP 模式下：SMTP 服务器、端口（默认 587）、登录邮箱、密码/授权码、发件邮箱地址均必填；发件人显示名可选；STARTTLS / SSL/TLS 直连二选一 |
| 自定义 Webhook | Webhook URL | 请求方法（默认 POST）、请求头（JSON） |

另有三点：

- 钉钉发送 Markdown 消息，设置了加签密钥时自动附加时间戳与签名；飞书发送文本消息，设置了密钥时附带签名；企业微信、Telegram 发送文本消息。Telegram 固定通过 `api.telegram.org` 发送。
- 自定义 Webhook 的请求体为 JSON：`{"message": "通知正文", "timestamp": "2026-01-02 15:04:05", "source": "xianyu-auto-reply"}`，请求头固定带 `Content-Type: application/json`，可用“请求头”追加或覆盖；状态码低于 300 视为成功，300 及以上视为失败，不检查响应内容。
- 其他 HTTP 渠道（Bark、钉钉、飞书、企业微信、Telegram）状态码须低于 300，且响应是 JSON 时不能带失败标记（`errcode`、`StatusCode` 非 0，`code` 非 0 且非 200，或 `ok` 为 `false`），否则视为失败。

保存渠道后用渠道行上的“测试”按钮验证；测试会直接向该渠道发送一条固定内容的测试通知，不受事件订阅和账号绑定影响。

## 邮件与 SMTP

- 系统 SMTP 由管理员在“通知设置”页底部的“SMTP 邮件配置”中保存（仅管理员可见），邮件渠道默认完整继承；开启“使用独立 SMTP”后，该渠道只使用自己填写的整套配置，两套配置不会混用。
- 实际发信至少需要 SMTP 服务器、登录邮箱和收件邮箱；未填发件邮箱地址时使用登录邮箱作为发件人。QQ 邮箱需使用授权码而不是登录密码。
- 默认启用 STARTTLS（常用于 587 端口）；勾选“SSL/TLS 直连”（常用于 465 端口）会改为直接 TLS，两个选项互斥。启用 STARTTLS 但服务器不支持时发送失败。
- 认证优先使用 `PLAIN`；服务器只提供 `LOGIN` 时自动改用 `LOGIN`。
- 使用 SendCloud 时，SMTP 登录账号填写 `API_USER`，密码填写对应 `API_KEY`，发件邮箱地址单独填写。
- 邮件主题固定为“闲鱼自动发货通知”，正文为纯文本。

## 投递、重试与“不确定”通知

业务通知先写入数据库的 outbox，再由后台 worker 每 2 秒领取一批（最多 20 条）发送，不会在订单或账号处理流程里等待外部网络。

- 发送失败会按 5 秒起、每次翻倍（最长 640 秒）的间隔重试；第 10 次尝试仍失败时标记为失败（`dead`），不再重试。
- 自动化终态通知使用“运行 ID + 终态”作为幂等键，同一终态不会重复入队。
- 外部渠道已经发送成功、但本地确认写库失败时，该条通知被隔离为“不确定”，**不会自动重发**，避免重复推送。管理员可通过管理 API 查看，见[管理API](管理API.zh-CN)。
- 仅配置了渠道不会让账号使用它：自动化结果通知还要求账号已绑定该渠道，且渠道的事件筛选包含对应类别。

Webhook 和机器人令牌通常等同于密码，不要贴进截图、Issue 或聊天记录。
