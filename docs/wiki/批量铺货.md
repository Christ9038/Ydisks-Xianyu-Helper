# 批量铺货

批量铺货会先预检，再启动后台发布任务。它最多一次处理 50 行商品；建议先用 1 行测试资料包验证后再跑正式批次。

## 1. 准备资料包

必需文件为 CSV、XLSX 或 TSV 表格；如引用本地图片，再提供 ZIP 图片包。下载“商品管理 → 批量铺货”中的模板可避免表头错误。

推荐中文表头：

```text
账号ID,标题,描述,价格,原价,库存,邮费模式,邮费,图片,类目ID,类目名称,频道类目ID,淘宝类目ID,付款发货启用,付款发货内容,评价赠品启用,评价赠品内容,求评价启用,求评价等待小时,求评价文案,求评价最多次数
```

也支持英文表头，但不能与中文混用。每行一个商品；`账号ID` 可留空并在上传页选择默认账号。

### 必填与格式

- 标题非空，价格大于 0；库存为正整数，留空默认 1。
- 邮费模式为 `free`/`包邮` 或 `fixed`/`固定邮费`；固定邮费时必须填邮费。
- 每件商品 1–9 张图片，多个用英文分号 `;` 分隔。可用公开 `https://` URL，或 ZIP 内相对路径。
- 上传页必须填写“批次兜底类目 ID + 类目名称”。表格的“类目ID + 类目名称”可选，用于覆盖某一行的批次兜底配置；两列必须同时填写。
- “频道类目ID”和“淘宝类目ID”通常留空，只有已取得同类闲鱼商品的准确值时才填写。
- 本地图片 ZIP 最大 200 MiB，单图最大 10 MiB；表格最大 20 MiB。
- CSV 使用 UTF-8，建议带 BOM；不要在表头增加空格。

### 自动化列

“付款发货内容”和“评价赠品内容”格式相同：

```text
卡密组ID:每件份数:延迟秒;卡密组ID:每件份数:延迟秒
```

例如 `101:1;102:2:30`：先从组 101 发 1 份，再等待 30 秒从组 102 发 2 份。份数省略时为 1，延迟省略时为 0。卡密组 ID 从“卡密库存”复制。启用值可写“是”、`true`、`1` 或 `on`；不启用写“否”、`false`、`0` 或留空。

完整字段规范和示例见仓库 [批量铺货资料包准备规格](../批量铺货使用文档.md)。

## 2. 后台操作

1. 在“商品管理”点击“批量铺货”。
2. 选择默认账号；表格某行未填账号 ID 时会使用它。
3. 填写批次兜底类目 ID 和名称。优先从同类型、已经同步或发布成功的历史商品复用，页面会提示已知的历史类目。
4. 选择表格；表格引用本地图片时同时选择 ZIP。
5. 点击预检，确认每一行显示的兜底类目正确，再处理账号未授权、卡密组不存在、图片路径不匹配、固定邮费缺失或价格为 0 等错误。
6. 所有需发布行确认无误后启动任务；不要关闭正在运行的任务页面。
7. 在任务详情查看成功、失败与进行中行。需要时取消任务；正在提交的单件商品可能继续完成。
8. 对可重试失败项使用“重试失败”，并下载结果 CSV 留档。

### 类目选择顺序

系统仍会先让闲鱼根据标题、描述和图片自动识别类目。只有闲鱼明确返回“未能自动识别商品类目”时，系统才会使用后备配置：优先使用表格当前行的“类目ID + 类目名称”，否则使用上传页的批次兜底类目。接口超时、鉴权失败、风控等错误不会被兜底类目掩盖。

批量铺货发布的都是虚拟商品，不请求或提交实物发货地址；指定类目只解决商品类型识别，不会改变虚拟发货流程。

## 3. 常见问题

- **图片找不到**：ZIP 内路径必须与表格完全一致，使用 `/`，不能以 `/` 开头或包含 `..`。
- **未能自动识别类目**：新建批次时必须设置兜底类目；如果仍出现该提示，通常是旧批次没有保存兜底配置，请重新上传创建任务。不要把接口超时或鉴权错误误当成类目问题。
- **类目 ID 从哪里取**：优先复用账号里同类型的历史商品类目。选择页面给出的历史类目，或从已同步商品的类目信息中复制 ID 和准确名称；不要猜测 ID。
- **自动化不生效**：检查卡密组 ID、账号归属、启用列和库存；发布成功后仍应查看自动化规则是否已创建。
- **任务中断**：先重新打开批次详情确认状态，避免重复新建整批任务；仅重试失败行。
