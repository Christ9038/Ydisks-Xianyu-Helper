# 常见问题（来自 Issue 的问答）

[English](FAQ) | 中文

整理自 Issue 的咨询类问题，按主题分组。Cookie / 风控问题见[风控处理](风控处理.zh-CN)。括号内是 Issue 编号；“vX 修复”表示升级到该版本或更高即可。

## 安装、升级与账号

**问：管理员账号是哪一个？忘记密码怎么办？**
答：用户名是 `admin`，首次打开管理页面时设置并确认密码。重置：`go run ./cmd/server -init-admin -db <数据库路径> -admin-password '<新密码>'`；Docker Compose 用户设置 `XIANYU_ADMIN_PASSWORD`（#70）。

**问：Docker 部署怎么升级？数据会保留吗？**
答：拉取最新镜像，删除旧容器并用原参数重新创建（Compose：`docker compose pull && docker compose up -d`；Portainer：拉镜像后 Recreate）。数据存放在挂载卷/数据库中，只要沿用原卷和 `XIANYU_DATA_KEY` 就会保留（#59）。

**问：部署在哪里合适？**
答：最好在家里用 NAS / 软路由 / 家用主机 Docker 部署；机房 IP 更容易被风控（#100）。

**问：能用 MySQL 吗？有微信群吗？**
答：除 SQLite 外支持 MySQL 与 PostgreSQL（见[部署与数据库](部署与数据库.zh-CN)）。只有 Telegram 群，没有微信群（#27）。

**问：macOS 安装包安装失败。**
答：安装包可能未签名。到“系统设置 → 隐私与安全性”允许被拦截的安装包后重新安装。反馈时请提供 macOS 版本、芯片（arm64/Intel）、安装包文件名与完整报错（#58）。

**问：Windows 安装包更新时提示“Windows 服务注册失败”。**
答：该 Issue 暂无确认的结论。可尝试以管理员身份运行安装包并先停止旧的 `YdisksXianyuHelper` 服务；仍失败请附完整报错提交 Issue（#26）。

**问：通知测试提示“拒绝访问非公网地址”。**
答：内置安全策略会拦截解析到内网 IP 的通知地址。如使用 fake-ip 模式的代理（如 mihomo），把通知服务域名加入 fake-ip 过滤列表即可（#9）。

**问：浏览器通知提示“权限已拒绝”，或没有声音。**
答：在浏览器站点设置里允许该站点通知（通常需 HTTPS 或 `localhost`）。提示音开关在“系统设置 → 基础设置”（#78、#95）。

**问：程序收发消息用的是官方 API 吗？**
答：参考官方网页版协议（WebSocket + MTOP），不是无头浏览器轮询页面（#17）。

## 商品、库存与发货

**问：API 制卡的请求头保存后再打开看不到了；卡密库存删不掉。**
答：API 卡的密钥出于安全不会回显到页面，编辑时需重新填写（#60）。卡密库存在规则删除后无法删除的问题 v1.0.8 修复（#31）。

**问：多规格商品总是命中不了自动发货。**
答：规则必须完整匹配订单的 SKU 组合。多规格匹配 v1.0.6 修复（#16），发货件数显示 v1.0.7 修复（#24）。

**问：自动化规则里账号下拉为空。**
答：v1.0.6 已优化；请确认已建立卡密库存且账号已启用（#20）。

**问：能对接卡商 API 发货吗？**
答：可以，v1.0.5 起支持 API 卡/自动发货（#12、#15）。

**问：二人小刀订单不发货 / 需要免拼。**
答：v1.0.13 起“自动免拼”是账号管理中的独立开关。顺序为：收到“待刀成”→（开启时）免拼 →收到“我已成功小刀，待发货”后才发卡 → 按“自动确认发货”开关确认发货（#49）。

**问：服务预约类 ¥0 订单为什么不发卡？**
答：付款自动发货增加了成交金额门禁，¥0 订单不会误发卡密（#104）。

**问：发布商品报 `INVALID_MAP_LOCATION`。**
答：实物商品必须提供位置，虚拟商品通常不要求。新版本发布时可选择发货地区（#1）。

**问：订单管理里的“导入订单”表格模板在哪？**
答：这是历史残留，请直接用订单同步（#36）。

**问：默认回复在我作为买家时也触发。**
答：账号默认回复作用于该账号的会话，建议用规则限定范围（#37，待改进）。

## 评价与 AI

**问：自动评价失效了。**
答：已知并已修复的原因：确认收货通知的订单号被误解析为阶段码 20（#76、#81、#83），以及 200 条候选窗口被已评价订单占满（#96）。请升级到最新版。超过 30 天的订单平台本身不允许评价（#42）。

**问：启用“超时未评价求评价”规则后一次发了近 100 条。**
答：已修复：求评价规则新增“仅处理最近 N 小时内发货的订单”回溯窗口，重新启用时不会再给历史订单发消息（#86）。详见[自动化规则](自动化发货与回复.zh-CN)。

**问：AI 回复没反应，模型测试却成功。**
答：Base URL 需是兼容 OpenAI 且以 `/v1` 结尾的地址，并使用 v1.0.13+ 的 AI 模型测试。目前 AI 回复仅用于自动砍价应答，不回答其他问题（#50）。

**问：买家发“转人工”能通知我吗？**
答：买家消息提醒仍由闲鱼 App 推送，暂未实现关键词通知（#34）。
