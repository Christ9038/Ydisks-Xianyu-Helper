# 部署与数据库

## 选择数据库

| 场景 | 建议 | 原因 |
| --- | --- | --- |
| 本机试用、单人低频使用 | SQLite | 无需额外服务，数据库是一个文件。 |
| Docker 生产部署 | PostgreSQL 17 | 默认 Compose 已提供服务、持久化卷和健康检查。 |
| 已有 MySQL 运维体系 | MySQL 8+ | 可复用现有备份、监控和权限管理。 |
| 多人或长期运行 | PostgreSQL / MySQL | 更适合并发、备份和独立运维。 |

三种数据库均会在应用启动时自动执行内置迁移。连接优先级是：`DATABASE_URL` > `-db-url` > `-db`。升级生产库前先备份。

## Docker + PostgreSQL（推荐）

1. 复制配置：`cp .env.example .env`。
2. 编辑 `.env`，至少设置 `POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD`、`XIANYU_DATA_KEY`、`XIANYU_ADMIN_PASSWORD`。
3. 为 `XIANYU_DATA_KEY` 生成一次长期固定的随机值，例如 `openssl rand -base64 48`；不要在后续升级时更换。
4. 启动：`docker compose up -d`。
5. 查看：`docker compose ps` 和 `docker compose logs -f app`。
6. 打开 `http://服务器地址:59188`。设置了 `XIANYU_ADMIN_PASSWORD` 时，Compose 会在首次启动
   自动创建 `admin`；如果使用其他方式启动且数据库尚未初始化，页面会显示初始化表单，填写
   两次不少于 8 个字符的密码即可。

> 安全提示：源码和容器使用 `-addr :59188` 时会监听全部接口。未初始化实例的网页首次初始化没有
> 预共享 secret，最先连到管理端口的客户端可以创建管理员。该便利行为不做 IP 限制，部署者必须在
> 防火墙、安全组或反向代理层限制访问；公网部署建议设置 `XIANYU_ADMIN_PASSWORD` 或先使用
> `-init-admin` 完成初始化。

默认连接已由 `compose.yml` 注入，不需要手写 PostgreSQL URL。若修改 `COMPOSE_PROJECT_NAME`，新卷名前缀也会变化；已有部署升级时保留原 `.env`，避免误用新空卷。

Docker 中的自动续期会使用容器内 Chromium 检测到的 Linux 原生浏览器指纹请求闲鱼官网；不会因为宿主系统是 Linux 而跳过静默续期。续期结果仍以闲鱼响应和账号登录态为准。

源码服务默认使用 `-addr :59188`，会监听全部网络接口；Docker Compose 端口映射默认也使用
`XIANYU_BIND_ADDRESS=0.0.0.0`。桌面安装包则显式绑定 `127.0.0.1:59188`。远程部署必须在防火墙、
安全组或反向代理层限制管理端口，不能把源码示例中的 `:59188` 误认为仅本机监听。

## 版本、镜像与正式发布

项目以 Git 标签作为正式版本来源，正式标签必须符合 `v1.2.3` 格式，并指向 `main` 已包含的提交。
推送正式标签后，统一的 `.github/workflows/release.yml` 会重新从该标签提交构建桌面安装包和 Docker 镜像；
不会复用之前 `main` 分支构建的产物。
构建、Chromium 启动和 `/health` 检查全部通过后，还需要 `production-release` Environment 人工审批，
审批通过才会创建 GitHub Release、上传安装包与 `SHA256SUMS`，并更新正式镜像标签。

Docker 标签规则如下：

| Git 引用 | 镜像标签 | 是否正式发布 |
| --- | --- | --- |
| `dev` 分支 | `dev`、`sha-<完整提交号>` | 否，用于日常调试 |
| `main` 分支 | `main`、`sha-<完整提交号>` | 否，稳定候选构建 |
| `v1.2.3` 标签 | `v1.2.3`、`1.2.3`、`1.2`、`latest`、`sha-<完整提交号>` | 是 |

`latest` 只在正式版本审批发布阶段更新，不会随 `main` 或 `dev` 分支提交变化。生产环境建议使用
`v1.2.3`、`1.2.3` 或 SHA 标签固定版本；Compose 默认使用 `latest`。

当前 Windows 和 macOS 正式安装包的 CI 签名步骤仍需要对应的签名证书 Secrets；未配置时这些平台的
正式发布会在签名步骤失败。Linux 安装包不依赖桌面端签名证书。

## 独立安装包

独立安装包与 Docker 使用同一套 Playwright Chromium 版本来源：Chromium、headless shell 和
Playwright driver 都在构建阶段下载并放入包内，不使用 Debian 仓库的 Chromium。Docker CI 会优先
复用架构专属的 GitHub Actions runtime 缓存，Dockerfile 最终使用固定的 Node.js 24 slim 运行时，
只通过 Playwright 安装 Chromium 所需系统动态库，随后清理 apt 索引和临时缓存，不安装 Debian
仓库中的 Chromium。安装时不需要用户再执行浏览器下载命令。

| 平台 | 安装方式 | 服务标识 | 默认地址 |
| --- | --- | --- | --- |
| Linux amd64/arm64 | 解压后以 root 执行 `./install.sh` | `ydisks-xianyu-helper.service` | `http://127.0.0.1:59188` |
| Windows | 运行 Inno Setup 安装器 | `YdisksXianyuHelper` | `http://127.0.0.1:59188` |
| macOS arm64/amd64 | 运行对应架构的 pkg 安装器 | `com.ydisks.xianyu-helper.server` | `http://127.0.0.1:59188` |

Windows 和 macOS 安装包还会安装独立的托盘/菜单栏控制器。控制器负责显示检查中、启动中、运行正常、
正在停止等中间状态，启动、停止和重启后台服务，打开日志目录，并在退出前等待后台服务确认停止。
Windows 安装阶段会授予交互式登录用户该服务的查询、启动和停止权限，因此日常托盘操作不需要
重复确认 UAC；修改服务配置或删除服务仍需管理员权限。Linux 没有桌面托盘，使用 systemd 和
`journalctl -u ydisks-xianyu-helper.service` 管理服务。

独立安装包的数据和日志位置为：Windows 的 `C:\ProgramData\YdisksXianyuHelper`，macOS 的
`~/Library/Application Support/YdisksXianyuHelper` 与 `~/Library/Logs/YdisksXianyuHelper`，Linux 的
`/var/lib/ydisks-xianyu-helper` 与 `/var/log/ydisks-xianyu-helper`。macOS 必须选择与 CPU 匹配的
arm64 或 amd64 包；Linux 也必须在相同架构的主机上安装，安装脚本不使用 QEMU。

本地 macOS 打包必须先构建前端与三个可执行文件，再调用唯一的打包脚本。脚本在 runtime 缺失时会自动
从本机 Playwright 缓存准备匹配的 driver、Chromium 和 headless shell：

```bash
npm ci --prefix frontend
npm run build --prefix frontend
mkdir -p dist/macos/arm64
go build -trimpath -ldflags='-s -w' -o dist/macos/arm64/xianyu-server ./cmd/server
go build -trimpath -ldflags='-s -w' -o dist/macos/arm64/browser-install ./cmd/browser-install
go build -trimpath -ldflags='-s -w' -o dist/macos/arm64/xianyu-tray ./cmd/tray
packaging/macos/build-pkg.sh 0.0.0-local "$PWD/dist/macos" arm64
```

Intel macOS 将上述 `arm64` 替换为 `amd64`，且需要本机已准备对应 x64 runtime。没有签名身份时生成的是
未签名 pkg，不可作为已签名分发包使用。

## 桌面端日志与操作

日志目录如下。Windows 和 macOS 托盘菜单还可以启动、停止或重启后台服务，打开管理页面和日志目录。
选择“退出托盘”时，会先停止后台服务，再退出托盘控制器，避免后台进程脱离用户控制继续运行。
Windows 安装器会在安装阶段一次性配置当前机器上该服务的最小控制权限。普通交互式登录用户之后可以从托盘查询、启动和停止 `YdisksXianyuHelper`，这些操作不需要再次确认 UAC；修改服务配置、删除服务和控制其他系统服务仍需要管理员权限。

- Windows：`C:\ProgramData\YdisksXianyuHelper\logs\server.log`
- macOS：`~/Library/Logs/YdisksXianyuHelper/server.log`，托盘日志为同目录下的 `tray.log`
- Linux：`/var/log/ydisks-xianyu-helper/server.log`，同时可用 `journalctl -u ydisks-xianyu-helper.service` 查看

桌面端首次使用时直接打开管理页面，在初始化页面填写并确认管理员密码即可，不需要查找数据库路径或打开终端。

## SQLite

适合开发或轻量单机。默认数据库路径为 `data/xianyu_data.db`：

```bash
go run ./cmd/server -db data/xianyu_data.db -addr :59188
```

上例会监听全部接口；仅本机使用时可改为 `-addr 127.0.0.1:59188`。

也可显式指定：

```bash
DATABASE_URL="sqlite://data/xianyu_data.db" ./xianyu-server
```

备份时先停服务，或使用 SQLite 在线备份工具；不要只复制正在写入的 WAL 数据库主文件。恢复时同时恢复数据库和原有 `XIANYU_DATA_KEY`。

## MySQL

先创建 UTF-8 数据库和最小权限账号，再为应用提供 URL：

```bash
DATABASE_URL="mysql://user:URL编码后的密码@tcp(db.example:3306)/xianyu" \
  ./xianyu-server -addr :59188
```

应用会补齐所需 MySQL 连接参数。密码中出现 `@`、`:`、`/` 等字符时必须 URL 编码。使用 TLS 的环境请按数据库驱动/基础设施要求配置安全连接，不要把真实密码写进命令历史。

## PostgreSQL（外部服务）

```bash
DATABASE_URL="postgres://user:URL编码后的密码@db.example:5432/xianyu?sslmode=require" \
  ./xianyu-server -addr :59188
```

仅在受信任的本机网络可考虑 `sslmode=disable`；公网或跨网络部署应使用 TLS。数据库账号只应拥有该应用数据库的必要权限。

## 初始化、备份和升级

### Web 页面初始化（推荐）

启动服务后访问管理页面。系统尚未存在管理员时，会显示“首次设置管理员密码”页面。输入并
确认不少于 8 个字符的密码，提交后系统会创建 `admin` 账号并自动登录。此流程不需要用户
知道 SQLite 文件路径，也不需要打开终端执行初始化命令。

### CLI 初始化（运维备用）

无浏览器、自动化部署或需要重置管理员密码时，可以使用 CLI：

```bash
go run ./cmd/server -init-admin -db data/xianyu_data.db -admin-password '强密码'
```

已有管理员时，仅确保其存在而不重置密码：

```bash
go run ./cmd/server -ensure-admin -admin-password '强密码'
```

PostgreSQL 备份示例：

```bash
docker compose exec -T postgres pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  > ydisks-backup.sql
```

升级顺序：备份数据库和 `.env` → 拉取/构建新镜像 → `docker compose up -d` → 查看日志确认迁移成功 → 登录检查账号和自动化任务。若迁移失败，停止继续操作并从备份恢复。
