# 砍价订单与自动发货流程

[English](Bargain-Orders-and-Delivery-Flow) | 中文

自动发货由闲鱼的 **WebSocket 系统消息**驱动。按订单状态扫描的调度器只是“消息丢了”时的兜底，绝不会抢在 WebSocket 阶段之前行动。本页说明四条发货路径、二人小刀订单的动作顺序，以及失败运行如何恢复。

## 三个账号开关

| 开关（账号管理） | 作用 |
| --- | --- |
| 自动发货 | 该账号付款后自动化的总开关。 |
| 自动确认发货 | 发卡或发送模板成功后，调用普通“确认发货”接口。 |
| 自动免拼 | 独立开关，只在收到“待刀成”消息时读取。 |

## 四条路径

| # | 场景 | 事件顺序 |
| --- | --- | --- |
| 1 | 常规发货 | 付款消息 → 读取金额、数量、规格 → 匹配发货规则 → 发卡/模板成功 → 按开关确认发货。 |
| 2 | 多规格发货 | 付款消息 → 读取订单**完整** SKU 组合 → 只执行完整匹配该组合的规则 → 发卡成功 → 按开关确认发货。不会按部分规格或猜测金额匹配。 |
| 3 | 二人小刀，未开自动免拼 | 忽略“待刀成”阶段 → 收到“我已成功小刀，待发货”后发卡/模板 → 按开关确认发货。 |
| 4 | 二人小刀，开启自动免拼 | “待刀成”消息 → **只调用一次**免拼 → 等“我已成功小刀，待发货”消息 → 发卡 → 按开关确认发货。 |

硬性规则：

- 订单还停在“待刀成”时，不发卡、不发模板、不确认发货。
- 发卡永远是确认发货前的最后一步。免拼不能替代确认发货，砍价订单同样调用普通确认发货接口。
- 关闭自动免拼，不会阻止已经到达“待发货”阶段的订单发卡。

## 安全门禁

- 缺订单号的付款事件一律拒绝，系统不会按会话去猜订单。
- 必须可靠取得购买数量后才会发货。
- 成交金额门禁会拦下 ¥0 订单（例如服务预约单），避免误发卡密。
- 商品不在本地商品库的订单会被静默跳过，不再误报“需要人工处理”。

## 兜底与恢复

- **待发货兜底**每分钟扫描一次：订单至少被观测为待发货 2 分钟、且还没有任何付款运行时才补触发，同一订单两次兜底至少间隔 10 分钟。兜底不会调用免拼；砍价订单只有已记录免拼成功、或已收到最终“待发货”阶段，才可补发卡与确认发货。
- **续跑未完成运行**只放行 `confirm_shipment` 这类幂等收尾动作，因为它们不会再次联系买家。
- 重放任何失败运行之前，都会重新核对：运行最初来自 WebSocket 或合法兜底、订单当前仍是 `pending_ship`、订单归属账号未变、账号仍开启自动发货。
- 订单已取消、完成或已发货时，旧运行会被取消；订单事实缺失、身份不一致或外部结果不确定时，停止自动重放并发送“需要人工处理”通知。
- 两条兜底链路可用 `XIANYU_PENDING_SHIP_CATCHUP=0` 一次性关闭，见[配置参考](配置参考.zh-CN)。

## 发货停住时看哪里

1. [自动化发货与回复](自动化发货与回复.zh-CN)中的“需要人工处理”面板与规则日志。
2. [订单管理](订单管理.zh-CN)查看已发卡密、必要时手动发货。
3. [运行日志](运行日志.zh-CN)按来源 `automation` 筛选。
4. 在通知渠道里勾选**需要人工处理**事件类别，这类停住才会通知到你。
