# 配置参考

[English](Configuration-Reference) | 中文

服务端所有配置入口：命令行参数、环境变量和 Docker Compose 的 `.env`。日志等级与格式以命令行参数优先于环境变量；**数据库连接例外：`DATABASE_URL` 环境变量优先于 `-db-url`，再优先于 `-db`。**

## 命令行参数（`cmd/server`）

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `-db` | `data/xianyu_data.db` | SQLite 文件路径（旧用法）。在 Windows/macOS 上，未传 `-workdir` 且仍为默认值时，实际落在平台数据目录下的 `data/xianyu_data.db`。 |
| `-db-url` | 空 | 数据库 URL（`sqlite://`、`mysql://`、`postgres://`），优先于 `-db`，但会被已设置的 `DATABASE_URL` 环境变量覆盖。 |
| `-addr` | `:59188` | HTTP 监听地址。`:59188` 监听所有网卡；桌面安装包固定为 `127.0.0.1:59188`。 |
| `-web` | 内置 | 指定含 `index.html` 的前端目录，替代内置前端。 |
| `-workdir` | 当前目录 | 工作目录；桌面服务用它固定数据和浏览器目录。 |
| `-data-key-file` | 空 | 持久化 `XIANYU_DATA_KEY` 的文件，不存在时自动生成；仅在没设置该环境变量时使用。留空时：有数据目录（`-workdir`，或 Windows/macOS 默认数据目录）用其中的 `data-key`，否则 SQLite 在数据库文件旁生成 `data-key`；MySQL/PostgreSQL 在两者都没有时拒绝启动。 |
| `-secure` | 关 | HTTPS 模式，会话 Cookie 带 `Secure`。放在 HTTPS 反向代理后面时开启。 |
| `-no-browser` | 关 | 禁用 Chromium，浏览器指纹读取和滑块自动处理将不可用。仅在确实无法运行 Chromium 的机器上使用。 |
| `-playwright-runtime-root`、`-playwright-driver-dir`、`-playwright-browser-dir` | 空 | 安装包自带 Playwright runtime 的位置，一般由打包后的服务自动传入，无需手填。 |
| `-log-level` | 空 | `debug` / `info` / `warn` / `error`，也支持按模块覆盖，如 `info,mtop=debug`；未指定时依次读 `LOG_LEVEL`、系统设置中的日志等级。命令行、`LOG_LEVEL` 或 `-v` 任一明确指定后，系统设置里的日志等级不再覆盖它。 |
| `-log-format` | 空 | `text` 或 `json`；未指定时读 `LOG_FORMAT`，再读数据库中的 `log_format` 设置，都没有则为 `text`。 |
| `-v` | 关 | 调试日志；仅在没有通过 `-log-level` 或 `LOG_LEVEL` 指定等级时生效。 |
| `-init-admin` | 关 | 创建或重置 `admin` 管理员后退出。 |
| `-ensure-admin` | 关 | 仅在 `admin` 不存在时创建，已存在则不改密码。 |
| `-admin-password`、`-admin-email` | 空 / `admin@example.com` | `-init-admin`、`-ensure-admin` 使用的凭据；密码也可来自 `XIANYU_ADMIN_PASSWORD`。 |
| `-service` | 关 | 以 Windows Service 模式运行（安装器自动设置）。 |
| `-version` | 关 | 显示版本与构建信息后退出。 |

## 环境变量

| 变量 | 作用 |
| --- | --- |
| `DATABASE_URL` | 数据库连接串，设置后优先于 `-db-url` 与 `-db`。密码里的特殊字符要做 URL 编码。 |
| `XIANYU_DATA_KEY` | 加密 Cookie、密码、AI 密钥、SMTP 和通知凭据的 AES-256-GCM 密钥。**设定后不要更换，并与数据库一起备份**；更换会导致已加密数据无法解密。 |
| `XIANYU_ADMIN_PASSWORD` | 非交互部署（Docker Compose）的初始 `admin` 密码；之后重启不会重置。 |
| `XIANYU_UPLOAD_DIR` | 上传图片和资源库文件的根目录，默认 `data/uploads`，Docker 为 `/app/data/uploads`。 |
| `XIANYU_LOG_DIR` | 日志文件目录，日志追加写入其中的 `server.log`；未设置时日志写到标准输出（Windows 上默认写到数据目录下的 `logs`）。Linux 安装包由 systemd 单元设置它。 |
| `LOG_LEVEL`、`LOG_FORMAT` | 同命令行参数；对接日志采集器时建议 `LOG_FORMAT=json`。 |
| `BROWSER_HEADLESS` | `true`/`1`/`yes`/`on` 强制无头 Chromium，`false`/`0`/`no`/`off` 强制有界面；不设置则由各浏览器任务自身的默认值决定（账号的“登录时显示浏览器”开关影响登录与验证流程的有界面/无头选择）。 |
| `XIANYU_PENDING_SHIP_CATCHUP` | 默认开启。设为 `0` 一次性关闭两条兜底链路（付款消息丢失后扫描待发货订单、续跑未完成运行）。详见[砍价订单与自动发货流程](砍价订单与自动发货流程.zh-CN)。 |
| `XIANYU_CONTINUE_AFTER_UNCERTAIN` | 默认开启。消息动作结果不确定时，若剩余动作全部是 `confirm_shipment`，则继续执行它（不会再联系买家、平台侧幂等），该运行最终仍收口为“需要人工处理”；设为 `0` 则整条链路直接停止。 |
| `TZ` | 进程时区，Compose 默认 `Asia/Shanghai`；每日擦亮始终按北京时间执行。 |
| `XIANYU_SERVICE_URL`、`XIANYU_SERVICE_NAME` | 仅托盘程序读取：后台服务地址（默认 `http://127.0.0.1:59188`）和服务标识（Windows 默认 `YdisksXianyuHelper`，macOS 默认 `com.ydisks.xianyu-helper.server`）。一般无需设置。 |

## Docker Compose 的 `.env`

`.env.example` 列出了 Compose 读取的变量：`COMPOSE_PROJECT_NAME`、`POSTGRES_IMAGE`（默认 `postgres:17-trixie`）、`POSTGRES_DB/USER/PASSWORD`、`DATABASE_URL`、`XIANYU_IMAGE`（默认 `ghcr.io/christ9038/ydisks-xianyu-helper:latest`）、`XIANYU_DATA_KEY`、`XIANYU_BIND_ADDRESS`（默认 `0.0.0.0`）、`XIANYU_HTTP_PORT`（默认 `59188`）、`XIANYU_UPLOAD_DIR`（默认 `/app/data/uploads`）、`TZ`（默认 `Asia/Shanghai`）、`LOG_LEVEL`（默认 `info`）、`LOG_FORMAT`（默认 `json`）、`BROWSER_HEADLESS`（默认 `true`）和 `XIANYU_ADMIN_PASSWORD`。其中 `POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD`、`DATABASE_URL`、`XIANYU_DATA_KEY`、`XIANYU_ADMIN_PASSWORD` 没有默认值，缺失时 Compose 会报错。应用容器以 `-addr :59188 -ensure-admin` 启动。

`XIANYU_CONTINUE_AFTER_UNCERTAIN` 在 `.env.example` 中是注释掉的可选项，Compose 默认把它传为 `1`。`XIANYU_PENDING_SHIP_CATCHUP` 同样是注释项，但 `compose.yml` 没有把它传入容器，仅写在 `.env` 里不会生效；需要关闭时要在 `compose.yml` 的应用环境中自行加入该变量。不要把 `.env` 提交到仓库。

## 健康检查

`GET /health` 无需登录即可返回服务状态（`status`、`database`、`version`、`commit`、`build_time`）；Docker 健康检查、桌面托盘和 `make smoke` 都依赖它。

另见[部署与数据库](部署与数据库.zh-CN)与[运行日志](运行日志.zh-CN)。
