# 自动化发货与回复（中文）

[English](Automated-Delivery-and-Replies) | 中文

## 自动化的四种触发器

| 触发器 | 触发时机 | 标准流程 |
| --- | --- | --- |
| 拍下未付款自动改价 | 收到买家拍下未付款卡片 | 匹配商品/规格 → 将订单改为目标价格 → 按需发送提醒文本。 |
| 付款后自动发货 | 收到付款系统卡片 | 匹配商品/规格 → 发送卡密 → 按账号开关决定是否确认发货。 |
| 评价后发送赠品 | 收到评价系统卡片 | 匹配商品/规格 → 发送赠品卡密。 |
| 超时未评价求评价 | 定时扫描已发货未评价订单 | 到达等待时间 → 发送提醒文案。 |

系统通知卡片只进入自动化判断。买家普通消息依次进入关键词回复、Agent 回复（需在“Agent 回复”页签启用）、AI 回复和默认回复。

付款提醒、成功小刀待发货卡片和评价提醒可能以不同版本的系统消息形式到达，系统会按交易消息语义识别；普通买家聊天不会触发上述交易自动化。账号绑定了通知渠道且事件筛选包含对应自动化类别时，自动化完成、失败或需要人工核对的终态会发送结果通知。

账号级自动评价和每日擦亮不属于上表的订单规则，配置入口在“账号管理 → 自动评价与每日擦亮”，执行方式见[在线聊天与账号自动任务](在线聊天与账号自动任务.zh-CN)。

“自动化规则”页有五个页签：交易自动化、关键词回复、账号默认回复、商品首次回复、规则日志。上表四种触发器在“交易自动化”页签点击“新建自动化”后选择；表单中还可设置“优先级”（数字越小越优先；同一账号、商品和触发条件只执行优先级最高的一条规则，商品级规则存在时账号级规则不会生效）和“启用规则”。

## 配置拍下未付款自动改价

1. 点击“新建自动化”，选择“拍下未付款自动改价”，选择账号和关联商品，并填写“目标价格（元）”（0.01–1000000 元，最多两位小数）。
2. 可选填写“改价后提醒买家”文本；留空时只执行改价。
3. 保存并启用规则。该规则只对尚未付款的订单生效；订单已付款、已关闭或平台拒绝改价时，任务会记录失败原因。

## 配置付款自动发货

前提：账号在线、账号已启用“自动发货”、商品已同步、卡密组已建立且有库存；是否把平台订单状态改为已发货由“自动确认发货”开关单独控制。

1. 进入“自动化规则 → 交易自动化”，点击“新建自动化”，选择“付款后自动发货”。
2. 设置规则名称，选择目标账号和商品；商品有规格时（多规格状态来自闲鱼商品本身，不能在此修改）为每个需要交付的规格填写“规格名称”和“规格值”（多 SKU 用“；”连接、按同顺序填写）。若不选商品而创建账号级规则，必须勾选“我确认此发货内容适用于该账号的全部商品”，未勾选时它不会作为商品缺少规则时的兜底。
3. 点击“添加发货内容”，选择“发货方式”（“卡密库存”或“发货模板”），选择卡密库存并填写“每件份数”（1–100）；同一规格可添加多条内容，买家付款后按顺序全部发送。
4. 如需覆盖卡密默认延时，勾选“覆盖卡密默认延时”并填写秒数（0–3600）；否则使用卡密的默认延时。
5. 勾选“启用规则”并保存。
6. 用测试订单确认：卡密内容已发送、卡密库存扣减正确；若账号启用了“自动确认发货”，再确认平台状态随后变为已发货。

如需接收自动化结果通知，还要在账号上绑定通知渠道，并在渠道事件中勾选对应的自动化类别。

按购买数量发货：动作中的“每件份数”会乘以订单购买数量。不要把每单总量误填为每件数量。

## 配置评价赠品与求评价

评价赠品的配置与付款发货相同，但触发器选择“评价后发送赠品”。赠品应使用独立卡密组，便于核对和补货。

配置求评价：

1. 新建自动化，选择“超时未评价求评价”，选择账号和商品。
2. 填写“发货后等待小时”（默认 72）、“再次求评间隔小时”（默认 24）及“最多求评次数”（默认 1）。
3. 设置“仅处理最近 N 小时内发货的订单”。发货时间早于该窗口的订单不会求评价，因此规则停用一段时间后重新启用，不会给历史订单补发消息。默认值为走完全部求评流程所需时长再加 24 小时，且不会小于首次等待时间。
4. 填写“求评价文案”，保存并启用。
5. 在测试订单上确认不会提前发送；达到最大次数后不再重复提醒。

## 异常处理与补发

“自动化规则”页面的异常区会列出可处理的自动化运行和延迟任务。先查看订单、库存、聊天记录和失败原因，再按情况选择“已执行，继续下一步”“未执行，安全重试”“终止”（延迟任务为“重新入队”“忽略”）。不要在不确定已发货状态时直接重试，以免重复发卡。

需要人工补发时，在订单管理中定位订单，确认买家、商品和历史交付记录，再使用手动发货/补发能力。处理后记录原因并检查库存。

付款自动发货正常只由平台的付款系统消息触发。该消息丢失、或订单在准备阶段就失败（连运行记录都不会产生）时，订单会永久停在待发货；调度器会每分钟扫描一次这类订单，并在本地最后一次观测到待发货状态至少 2 分钟后才按订单状态补一次触发，给实时付款卡片优先建立运行记录。自动免拼是账号级独立开关：只在收到“我已小刀，待刀成”WebSocket 卡片时按开关调用免拼；后续收到“我已成功小刀，待发货”卡片才发卡或发送发货模板，随后才可按开关走普通确认发货。兜底不会调用免拼；砍价订单只有在已记录免拼成功阶段后，才可在最终卡片丢失时补发卡和普通确认发货。订单一旦产生过任意 `order_paid` 运行就不再被兜底选中，后续走异常区的失败运行；同一订单两次兜底之间至少间隔 10 分钟；每轮最多实际触发 20 笔、共享 30 秒预算，超出的订单留给下一轮；同一运行最多被续跑 5 代。未完成的待发货运行也会被兜底续跑，但只放行 `confirm_shipment` 这类不会再次联系买家、平台侧幂等的收尾动作。把 `XIANYU_PENDING_SHIP_CATCHUP` 设为 `0` 可以一次性关闭这两条兜底链路。

## 关键词与默认回复

在“自动化规则”的“关键词回复”页签：选择账号 → 点击“新增关键词” → 保存。关键词规则用于买家普通消息。

- **表达式**：一条规则可添加多个表达式并共用同一条回复，任一命中即触发；“包含匹配”下，单个表达式还可用 `|`、逗号或换行写多个候选词。
- **匹配模式**：可选“包含匹配”或“正则表达式”。正则使用 Go/RE2 语法并忽略大小写，页面会先预校验，保存时服务端再次校验。
- **关联商品**：一条规则可关联多个已同步商品；不选表示账号级规则。
- **回复类型与内容**：可选“文字”或“图片”，分别填写回复内容或回复图片。

默认回复处于当前生产回复链路的最后一级：关键词回复优先，其次是 AI 回复，最后才是默认回复。AI 默认仅处理砍价场景（账号 AI 设置的工作模式“仅砍价”）；设为“全场景客服”后，也会回复未命中关键词的商品咨询、发货和售后等普通消息；商品还可单独强制启用或停用 AI（见[商品管理](商品管理)）。AI 未启用、未配置 API Key、消息不适用、没有可用结果或调用失败时，都会继续尝试默认回复。账号默认回复在“账号默认回复”页签（按钮“编辑默认回复”）维护，可设置启用开关、文本、图片和“同一会话只发送一次默认回复”；指定商品默认回复优先于账号默认回复。启用 Agent 回复后，它排在关键词回复之后、AI 回复之前（详见下节）。

## Agent 回复

“自动化规则”的“Agent 回复”页签可把未命中关键词的买家消息（文字或图片）转发给你自建的外部 HTTP Agent，并把 Agent 返回的多条文字或图片回复发给买家。优先级为：关键词回复 → Agent 回复 → AI 回复 → 默认回复。未启用或未配置时行为与之前完全一致；Agent 返回 `handled:false` 或首次请求失败时，会继续由 AI 回复和默认回复处理。

协议 v1：助手向配置的地址 POST JSON，可选 `Authorization: Bearer <token>`。请求字段为 `version`、`event`（`message`、`poll`、`ping`）、`turn_id`、`sequence`、`account_id`、`chat_id`、`item_id`、`buyer` 与 `message`；响应字段为 `handled`（缺省为 true）、`working`、`replies`（每项含 `text` 或 `image_url`）与 `poll_after_ms`。`working` 为 true 时助手按 `poll_after_ms` 继续发送 `poll` 事件。

- 单次请求超时 5–30 秒（默认 15），响应体最大 256 KiB，单轮对话最长 10–300 秒（默认 120），轮询间隔限制在 1–10 秒，单轮最多 60 次请求。
- 单轮最多发送 10 条回复，其中图片最多 3 张；发送结果不确定时立即结束本轮，不重试。
- 同一会话来新消息时会取消并替换进行中的旧轮次。
- Agent 不能触发自动改价；访问令牌加密保存，页面只显示“已配置”，日志和错误不含令牌。
- “测试连接”按钮发送不含买家数据的 `ping` 事件。

## 商品首次回复

规则页 → **商品首次回复**页签（按钮“新增首次回复”）。买家首次咨询所选商品时，系统自动发送一次预设文字（可附图片 URL）。

- 规则包含名称、启用开关、回复文字、可选图片 URL，以及该账号下的一个或多个商品。同一账号下**一个商品只能属于一条规则**，冲突会被拒绝。
- 文字可使用变量 `{send_user_name}`、`{send_user_id}`、`{send_message}`、`{item_id}`。
- 同一买家会话、同一商品只发送一次，已发送记录可清除。发送失败只写日志，不阻断原回复链路；已触发首次回复的会话，账号默认回复的“只回复一次”会让位给它。

## 规则日志

规则页 → **规则日志**页签是自动化行为的只追加审计，用于查看是否发货、发了什么、为什么被跳过。

- 可按状态（成功、失败、排队中、执行中、已跳过、待人工、已取消）、触发类型和订单号过滤，并打开订单的**运行时间线**。
- 事件覆盖跳过、排队、运行开始、动作成功/失败、终态、免拼结果和延期任务死信。只保存摘要，不保存卡密或消息正文；已发卡密默认遮罩，按需读取。
- 超过 90 天的事件每日自动清理。
- 需要人工处理的运行会列在“需要人工处理的自动化任务”面板，并触发独立的**需要人工处理**通知类别；请在通知渠道的事件筛选中勾选（原有自动化类别订阅保持兼容）。
