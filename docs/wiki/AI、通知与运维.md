# AI、通知与运维

## 配置 AI 服务

系统级连接在“系统与 AI”设置，仅管理员可修改：

1. 填写 OpenAI 兼容的 API 地址，填到版本根路径即可，例如 `https://api.openai.com/v1` 或通义兼容地址 `https://dashscope.aliyuncs.com/compatible-mode/v1`；不要填 `/chat/completions`。
2. 填入 API Key，点击“读取模型”。若服务不支持模型列表，也可手动填模型名。
3. 保存系统设置。API Key 会作为敏感字段保存；仍应限制数据库和管理员访问。
4. 前往“账号管理”，在目标账号行打开“AI 设置”。
5. 打开“启用 AI 自动回复”，配置最大折扣比例、最大降价金额、最大砍价轮次和自定义提示词，保存。
6. 使用真实但无风险的砍价对话测试输出；确认金额边界和措辞均符合预期后再开启正式账号。

AI 用于处理买家的砍价消息。`0` 的最大折扣比例或金额表示不允许对应降价；砍价轮次应设置保守值。提示词应明确产品边界、禁止承诺事项、语气和转人工条件，不应放入 Cookie、密码、完整订单隐私或其他机密。

## 配置通知

1. 打开“通知设置”，先按需要配置系统 SMTP（仅邮件渠道需要）。邮件渠道默认完整继承系统 SMTP；如需使用另一套发件服务，打开“使用独立 SMTP”并填写完整的独立 SMTP 配置。
2. 新建通知渠道，选择 Bark、钉钉、飞书、企业微信、Telegram、邮件或自定义 Webhook，并填写该渠道所需地址/令牌。
3. 选择接收事件；不选择表示接收全部。可选事件包括掉线、恢复、禁用、安全验证、续期、交易结果和系统错误。
4. 保存后点击“测试通知”，在目标渠道确认收到。
5. 回到“账号管理 → 编辑”，把通知渠道绑定到具体账号。仅创建渠道不会自动让账号使用它。

Webhook 和机器人令牌通常等同于密码。不要贴进截图、Issue 或聊天记录；更换令牌后立即更新渠道并重测。

## 日常巡检

每天或每次大促前检查：

- Dashboard 的在线账号、订单、库存和异常趋势；
- 自动化异常/延迟任务是否有待处理项；
- 批量卡密库存是否低于安全线；
- 最近一次通知是否可达；
- 登录续期和安全验证是否需要人工操作。

## 故障排查顺序

1. **账号不在线**：检查账号是否被暂停、Cookie 是否失效、是否需要扫码或安全验证；完成后确认恢复通知。
2. **未自动发货**：核对订单所属账号、商品/规格匹配、规则启用、卡密库存和自动化异常。先确认是否已经实际发送过内容。
3. **AI 无回复**：确认系统 API 地址、Key 和模型可用；再确认该账号 AI 已启用，且消息属于砍价场景。
4. **通知未达**：先点击测试通知，再核对事件筛选与账号绑定；邮件还需检查 SMTP 配置。
5. **数据库无法连接**：检查 `DATABASE_URL`、网络/TLS、数据库账号权限和服务日志。不要通过删除数据库来“修复”。

## 备份与恢复

备份至少包含数据库、`.env`（特别是 `XIANYU_DATA_KEY`）和必要的上传资源。恢复到新机器时先恢复数据库与同一把密钥，再启动服务；若密钥不一致，已加密的 Cookie、AI 和通知配置不可读取。恢复后先禁用高风险自动化，用测试订单逐项确认。
