# 风控处理（问答）

[English](Risk-Control-Troubleshooting) | 中文

本页整理 Issue 中最常见的闲鱼风控咨询，例如“闲鱼要求安全验证，请重新扫码并完成验证”“接口续期已更新登录凭证，正在重新连接”“`PERMISSION_EXCEPTION`”。依据 Issue #32、#48、#53、#64、#77、#92、#93、#100。

> 风控是**平台侧**针对 Cookie / IP / 设备做出的判断，不是程序缺陷。程序不会也无法替你绕过人脸或滑块验证，只能保证自己的请求频率足够低，并允许你导入一个已经通过验证的 Cookie。

## 为什么反复扫码没用？

**问：扫码很多次，一直提示“闲鱼要求安全验证”，为什么？**

答：账号被风控期间，每次扫码拿到的都是**同样带风控标记的新 Cookie**，再扫也一样。必须先在真实浏览器中把风控过掉，再把过了风控的 Cookie 交给系统。

## 推荐恢复流程

**问：Cookie 被风控后怎么处理？**

1. 在**与程序相同网络环境**的电脑浏览器上打开闲鱼网页版（`goofish.com`），登录该账号。
2. 进入**消息**页面。出现滑块、人脸或短信验证就完成它（没有弹出验证时见下一问）。
3. 打开浏览器开发者工具 → **网络（Network）**面板，刷新消息页，在请求列表中搜索 `token`。
4. 点开该 `token` 请求，复制**请求头里的 `Cookie`**（是“请求携带的 Cookie”，不是应用面板或其他标签里看到的 Cookie）。
5. 在管理后台 **账号管理 → 编辑账号** 中粘贴 Cookie 并保存，确认账号变为在线。
6. 之后不要立即重新扫码，等账号稳定。

切勿把 Cookie 贴到 Issue、群聊或截图里。

## 排查清单

**问：粘贴了 Cookie 仍然失败，或保存的 Cookie 在登录失败后消失了。**

答：平台仍拒绝的 Cookie 会被系统丢弃。依次检查：

- 网页版是否真的通过了验证？Issue #92 中成功的案例是第二次复制时网页才弹出滑块；若网页一直没要求验证，很可能复制到的是风控触发之前的 Cookie。
- 复制的是 **`token` 请求**的 Cookie，而不是随便一个 Cookie？
- 浏览器与服务器的出口网络是否一致？开关 VPN、切换代理或地区都会换 IP 并再次触发验证（Issue #48：切 VPN 后五分钟内 Cookie 又失效）。
- 网页版自己正显示验证页时，不要复制 Cookie。
- 间隔数小时后重试。Issue #93 中账号几小时后自行恢复；也有用户反馈重启容器后被风控的账号有时会恢复。

**问：日志提示“WS Token 即将到期，正在主动轮换”，一直恢复不了。**

答：说明用的不是刚通过验证的新 Cookie。请按上面的流程，用通过验证后立即发出的请求的 Cookie 重新导入（Issue #92）。

**问：同步订单报 `PERMISSION_EXCEPTION::无权限访问`。**

答：该 Cookie 的订单详情接口被风控（Issue #53）。登录官方网页版，进入“我的闲鱼”，点开一个商品/订单触发并通过验证，再把过了风控的 Cookie 粘贴回账号，然后重新同步。建议升级到 v1.0.13 及以上。

**问：反复出现“接口续期已更新登录凭证，正在重新连接”。**

答：这是协议级续期流程，通常表示凭证仍带风控标记，按上面的恢复流程处理。1.0.11 的续期策略偏激进，1.0.12 已降低频率，请使用较新版本。

## 预防

**问：部署在哪里更不容易被风控？**

答：最好在自己家里，用 NAS、软路由或家用主机 Docker 部署。机房/云服务器 IP（包括香港服务器）特征明显，容易被平台识别（Issue #100）。保持出口 IP 稳定，不要频繁切换 VPN/代理节点。

**问：可以加 `-no-browser` 启动吗？**

答：不建议。浏览器验证和订单详情兜底依赖 Chromium；只有确实无法使用 Chromium 时才关闭（Issue #48、#77）。

**问：程序会高频请求平台吗？**

答：不会。所有 MTOP 请求都经账号级节流器（间隔不低于 2 秒，后台批量任务不低于 5 秒），批量任务遇到风控会立即终止。请勿同一账号在多处同时运行，或多台机器共用一个账号。

**问：网络短暂中断后账号会一直离线吗？**

答：拨号失败会按 5 秒、15 秒、30 秒、60 秒、之后每 120 秒退避重试，只有平台明确拒绝才会终止账号（Issue #80，v1.0.13 之后修复）。出现 `wsarecv ... forcibly closed`、`server misbehaving` 之类（Issue #7、#32）是本机网络/DNS 问题，并非接口失效。
