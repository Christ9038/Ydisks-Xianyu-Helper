# 卡密库存使用手册（中文）

[English](Card-Inventory) | 中文

## 新建卡密组

1. 进入“卡密库存”，点击“添加新卡密”。
2. 填写卡密名称和可选描述。
3. 选择交付类型并填写内容：

| 类型 | 用途 | 内容填写方式 |
| --- | --- | --- |
| 文本 | 固定说明、链接或文字 | 每次发货发送相同内容。 |
| 批量库存 | 兑换码、序列号、账号密码 | 每行填写一条，发货时逐条消耗。 |
| 图片 | 固定图片资源 | 从[本地资源库](资源库.zh-CN)图片库选择图片（发货时由服务端读取），或填写可访问的外链图片 URL（发货时临时下载并上传到闲鱼）；二者互斥。 |
| API（界面显示“API 接口”） | 从外部系统动态取码 | 按页面填写 API 地址、请求方法（GET/POST）、超时（1–60 秒，默认 10）、请求头、查询参数、请求正文和响应提取路径（可选）。 |

4. 按需要填写“延时发货（秒）”，范围为 0 至 3600；0 表示立即发货。
5. 点击“添加卡密”保存。新建的卡密组默认启用；之后可在列表的状态开关或编辑弹窗的“启用状态”中切换。
6. 记录卡密组 ID（列表中点击 ID 即可复制），后续配置自动化规则或批量铺货时需要使用。列表可按类型和名称筛选。

## 补充批量卡密

- 新建卡密组时可以在内容框中逐行录入。
- 已有“批量库存”时，点击“批量导入”，切到“往单个组充卡密”页签，选择目标卡密组并每行填写一个卡密，点击“追加卡密”追加库存；空行自动忽略。
- 导入完成后检查成功数量和失败行；不要把同一批卡密重复导入。

## 批量创建卡密组

在“批量导入”窗口切到“批量创建卡密组”，上传 `.xlsx`、`.csv` 或 `.tsv` 表格即可一次建立多个卡密组，每行一组，表头为 `名称,类型,内容,描述,启用,延迟秒,多规格,规格名,规格值`，可先点“下载模板”。类型填 `text`/`data`/`image`；`data` 类型的内容按行存卡密（CSV 单元格内换行需用引号包裹）；“启用”留空时默认启用，“延迟秒”留空为 0（范围 0–3600）。单次最多 200 行，上传文件不超过 6 MiB。创建后在结果里核对成功与失败行；失败行修正后可重试，不要重复导入已成功的行。批量铺货表格里引用的“卡密组 ID”可在卡密列表中一键复制。

## API 卡密

API 卡密适合由外部发码系统按订单取码。可粘贴 cURL 命令自动填充请求，已保存的卡密可重新打开编辑，并无需重填密钥即可测试。启用幂等重试时，`{idempotency_key}` 必须出现在实际发送的请求头、查询参数或请求正文中，否则保存会被拒绝，发货时也只发起一次请求。页面支持测试接口；先用无敏感测试数据确认响应格式，再启用正式自动化。保存后的请求头、参数和密钥不会在列表中显示；重新打开编辑时敏感模板留空即沿用已保存的值。请求头、参数和密钥属于敏感信息，不要在截图或聊天中公开。

请求头、查询参数和请求正文中可使用以下变量（发送时替换为本次订单的值）：

| 变量 | 含义 |
| --- | --- |
| `{order_id}` `{item_id}` `{buyer_id}` `{chat_id}` | 订单号、商品 ID、买家 ID、会话 ID |
| `{account_id}`（同 `{cookie_id}`） | 账号 ID |
| `{spec_name}` `{spec_value}` | 订单规格名与规格值 |
| `{quantity}`（同 `{order_quantity}`） `{amount}`（同 `{order_amount}`） | 购买数量、订单金额 |
| `{item_detail}` `{trigger_type}` `{timestamp}` | 商品详情、触发类型、UTC 时间戳（RFC3339，含纳秒） |
| `{delivery_unit_index}` `{delivery_total_count}` | 本次是第几份、共几份（购买多件时每份单独请求） |
| `{idempotency_key}` | 同一份卡密在重试时保持不变的幂等键；启用重试时必须出现在请求中，最多请求 3 次 |

“启用幂等重试”勾选后，同一份卡密最多请求 3 次；未勾选时只请求一次。响应提取路径应填写实际返回字段，例如 `data.card.code`；如果外部接口返回结构发生变化，应先停用该卡密组，避免自动发货反复失败。

## 编辑、停用与删除

- 停用卡密组后，自动化不应继续使用它；适合临时维护或库存不足时使用。
- 修改延时只影响后续发货，已经发送的内容不会改变。
- 删除会先弹出确认框；系统不会替你检查引用，删除前请自行确认没有自动化规则或批量铺货任务引用该卡密组。
- 上线前至少检查：卡密组已启用、库存充足、卡密内容没有多余空格或空行。

## 售出台账（已售/未售）

在列表操作列点击“库存记录”图标，打开卡密组的**库存记录**弹窗（批量卡密、API 卡均有该入口）：

- **未售**页签（仅批量卡密有；API 卡每次发货时远端取码，只有已售页签）：剩余卡密（预览只显示前一部分）和**导出未售 TXT**（一行一条，可再次导入）。
- **已售**页签：每次发出的卡密、状态、订单号和时间；可按状态（全部状态/已售/待核对）筛选、按订单号（精确匹配）或卡密内容搜索，并**导出已售 CSV**（列：卡密、状态、卡密组、账号、订单号、商品ID、买家ID、售出时间（北京时间））。
- 状态 **sold** 表示发送已确认；**待核对**（`reserved`）表示发送结果不确定，需要人工核对，请勿盲目重发。
- 扣库存与台账记录在同一事务内写入。台账上线之前已发出的卡密不在记录内。
- 记录仅所属用户可见。单个订单已发出的卡密也可在订单页查看（见[订单管理](订单管理.zh-CN)）。
