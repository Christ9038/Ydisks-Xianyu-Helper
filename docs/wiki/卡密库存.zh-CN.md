# 卡密库存使用手册（中文）

[English](Card-Inventory) | 中文

## 新建卡密组

1. 进入“卡密库存”，点击“添加新卡密”。
2. 填写卡密组名称和可选描述。
3. 选择交付类型并填写内容：

| 类型 | 用途 | 内容填写方式 |
| --- | --- | --- |
| 文本 | 固定说明、链接或文字 | 每次发货发送相同内容。 |
| 批量库存 | 兑换码、序列号、账号密码 | 每行填写一条，发货时逐条消耗。 |
| 图片 | 固定图片资源 | 填写可访问的图片 URL，发货时临时发送。 |
| API | 从外部系统动态取码 | 按页面填写地址、请求方法、参数和响应路径。 |

4. 按需要填写“延时发货（秒）”，范围为 0 至 3600；0 表示立即发货。
5. 确认“启用状态”后保存。
6. 记录卡密组 ID，后续配置自动化规则或批量铺货时需要使用。

## 补充批量卡密

- 新建卡密组时可以在内容框中逐行录入。
- 已有“批量库存”时，点击“批量导入”并选择目标卡密组，可以追加库存。
- 导入完成后检查成功数量和失败行；不要把同一批卡密重复导入。

## 批量创建卡密组

在“批量导入”窗口切到“批量创建卡密组”，上传表格即可一次建立多个卡密组，每行一组，表头为 `名称,类型,内容,描述,启用,延迟秒,多规格,规格名,规格值`，可先下载模板。创建后在结果里核对成功与失败行；失败行修正后可重试，不要重复导入已成功的行。批量铺货表格里引用的“卡密组 ID”可在卡密列表中一键复制。

## API 卡密

API 卡密适合由外部发码系统按订单取码。可粘贴 cURL 命令自动填充请求，已保存的卡密可重新打开编辑，并无需重填密钥即可测试。启用幂等重试时，`{idempotency_key}` 必须出现在实际发送的请求头、查询参数或请求正文中，否则保存会被拒绝，发货时也只发起一次请求。页面支持测试接口；先用无敏感测试数据确认响应格式，再启用正式自动化。请求头、参数和密钥属于敏感信息，不要在截图或聊天中公开。

常用订单变量包括订单号、商品 ID、买家 ID、账号 ID、购买数量、金额和触发类型。响应路径应填写实际返回字段，例如 `data.card.code`；如果外部接口返回结构发生变化，应先停用该卡密组，避免自动发货反复失败。

## 编辑、停用与删除

- 停用卡密组后，自动化不应继续使用它；适合临时维护或库存不足时使用。
- 修改延时只影响后续发货，已经发送的内容不会改变。
- 删除前确认没有自动化规则或批量铺货任务引用该卡密组。
- 上线前至少检查：卡密组已启用、库存充足、卡密内容没有多余空格或空行。

## 售出台账（已售/未售）

打开卡密组的**库存记录**弹窗（批量卡密、API 卡均支持）：

- **未售**页签：剩余卡密（预览只显示前一部分）和**导出未售 TXT**（一行一条，可再次导入）。
- **已售**页签：每次发出的卡密、状态、订单号和时间；可按状态筛选、按订单号或卡密搜索，并**导出已售 CSV**。
- 状态 **sold** 表示发送已确认；**待核对**（`reserved`）表示发送结果不确定，需要人工核对，请勿盲目重发。
- 扣库存与台账记录在同一事务内写入。台账上线之前已发出的卡密不在记录内。
- 记录仅所属用户可见。单个订单已发出的卡密也可在订单页查看（见[订单管理](订单管理.zh-CN)）。
