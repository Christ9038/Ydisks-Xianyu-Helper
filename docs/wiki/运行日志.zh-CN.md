# 运行日志

[English](Runtime-Logs) | 中文

**运行日志**（`/app/logs`）展示服务进程内存中保留的最近日志，无需登录服务器翻文件即可排查问题。**仅管理员可打开该页面。**

## 功能

- **过滤**：按最低等级（全部等级 / Debug 及以上 / Info 及以上 / Warn 及以上 / 仅 Error）、**来源**和关键字（不区分大小写，匹配消息、请求方法、路径、接口名、失败分类、`ret`、错误文本或属性值）。
- 来源包括：内部接口（`http`）、闲鱼接口（`mtop`）、自动化、消息引擎、WebSocket、凭证续期、通知投递、其他。
- 页面每 2 秒自动增量读取一次；**暂停/继续**自动轮询，**刷新**从头重新加载，**清屏**（仅清空显示），以及“自动滚动到最新”。
- 每行直接显示请求、路由、状态码、耗时、失败分类、平台返回（`ret`）、账号、商品、订单、会话、运行 ID 和请求标识等标签（有值才显示），并显示写出该日志的源码位置；点击“属性”可展开其余附加属性。属性值在离开服务端前已脱敏，不会出现 Cookie 或 Token。

## 注意事项

- 内存中只保留有限条数的最近记录（默认 2000 条，页面会显示“服务端保留 N 条”），旧记录被挤出时页面会出现黄色提示；服务重启后缓冲清空。需要长期留存请查看日志文件（见[部署与数据库](部署与数据库.zh-CN)）。
- 记录是否进入缓冲取决于日志等级。默认 `info` 级别下，内部接口的成功读请求、MTOP 请求开始等 `debug` 记录不会出现；成功的写操作、MTOP 请求完成（含接口名、状态码、耗时）为 `info`，失败为 `warn`/`error`。需要全部明细，请在“系统设置”把日志等级调为 `debug`；日志等级也支持按模块覆盖，例如 `info,mtop=debug`。
- 同一调用点的重复 `warn`/`error` 日志每分钟只放行有限条数，其余只计数并以汇总记录补记。
- 该页面自身的轮询请求不会写入请求日志，不会自我刷屏。
- 典型用法：来源选 `mtop`、关键字填 `RGV587`，确认是否触发风控，参见[风控处理](风控处理.zh-CN)。
