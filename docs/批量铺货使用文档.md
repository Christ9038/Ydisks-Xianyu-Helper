# 批量铺货资料包准备规格（AI Agent 指南）

> 本文档面向负责**准备资料**的 AI agent。你的任务是产出一份符合规格的商品表格（和可选的图片压缩包），交给运营人员通过后台"批量铺货"功能上传上架。
>
> **你不负责提交上传、不负责调用接口、不负责跑发布流程。** 你只产出文件。下面是文件必须满足的规格。

---

## 1. 你的交付物

| 交付物 | 必填 | 格式 | 说明 |
|---|---|---|---|
| 商品表格 | 是 | `.csv` / `.xlsx` / `.tsv` | 每行一个商品，第一行表头 |
| 图片压缩包 | 条件必填 | `.zip` | 仅当表格里有图片用本地路径引用时才需要；全用公网 URL 则不需要 |

**命名建议：**
- 表格：`商品清单_YYYYMMDD.csv`（或 `.xlsx`）
- 图片包：`images.zip`（或 `图片包_YYYYMMDD.zip`）

把两个文件放在同一目录交付即可。

---

## 2. 表格规格

### 2.1 表头（第一行）

**推荐用中文表头**，复制下面这一行（表头匹配规则见本节末尾）：

```
账号ID,标题,描述,价格,原价,库存,邮费模式,邮费,图片,类目ID,类目名称,频道类目ID,淘宝类目ID,付款发货启用,付款发货内容,评价赠品启用,评价赠品内容,求评价启用,求评价等待小时,求评价文案,求评价最多次数,求评价延迟秒
```

如果用英文表头，对应是：

```
cookie_id,title,description,price,original_price,quantity,postage_mode,postage,images,category_id,category_name,channel_category_id,tb_category_id,paid_delivery_enabled,paid_delivery_contents,review_gift_enabled,review_gift_contents,review_request_enabled,review_request_after_hours,review_request_message,review_request_max_attempts,review_request_delay_seconds
```

> 建议中英文表头二选一，**不要混用**。系统是逐列识别表头的，混用不会被整体拒绝，但容易填错，不推荐。

**表头匹配规则（以 `batch_preview.go` 的 `normalizeHeader` 为准）：**

- 匹配前会去掉首尾空白、UTF-8 BOM，转为小写，并删除表头中的空格、下划线 `_` 和连字符 `-`，全角括号转半角；因此 `Cookie_ID`、`cookie id`、`账号ID`、`账号id` 等写法等价。
- 除上面的标准表头外，还接受下列别名（同一列只需使用其中一个）：

| 字段 | 可识别的表头别名 |
|---|---|
| 账号ID | `cookie_id`、`账号ID`、`账号`、`闲鱼账号` |
| 标题 | `title`、`itemtitle`、`标题`、`商品标题`、`商品名称` |
| 描述 | `description`、`desc`、`itemdescription`、`描述`、`商品描述`、`商品详情` |
| 价格 | `price`、`itemprice`、`价格`、`商品价格` |
| 原价 | `original_price`、`原价` |
| 库存 | `quantity`、`库存`、`数量` |
| 邮费模式 / 邮费 | `postage_mode`、`邮费模式` / `postage`、`邮费` |
| 图片 | `images`、`image`、`图片`、`商品图片` |
| 类目ID | `category_id`、`catid`、`类目ID`、`商品类目ID` |
| 类目名称 | `category_name`、`catname`、`类目名称`、`商品类目名称`、`类目` |
| 频道类目ID | `channel_category_id`、`channelcatid`、`频道类目ID` |
| 淘宝类目ID | `tb_category_id`、`tbcatid`、`淘宝类目ID` |
| 付款发货启用 / 内容 | `paid_delivery_enabled`、`付款发货启用`、`付款后自动发货` / `paid_delivery_contents`、`付款发货内容`、`付款后发送的卡密` |
| 评价赠品启用 / 内容 | `review_gift_enabled`、`评价赠品启用`、`评价后发送赠品` / `review_gift_contents`、`评价赠品内容`、`评价后发送的卡密` |
| 求评价启用 | `review_request_enabled`、`求评价启用`、`超时未评价时提醒` |
| 求评价等待小时 | `review_request_after_hours`、`求评价等待小时`、`发货几小时后提醒` |
| 求评价文案 | `review_request_message`、`求评价文案`、`提醒内容` |
| 求评价最多次数 | `review_request_max_attempts`、`求评价最多次数`、`最多提醒几次` |
| 求评价延迟秒 | `review_request_delay_seconds`、`求评价延迟秒` |

- 不能识别的表头列会被忽略；缺少必填列时，对应行在预检中报错。
- 后台“批量铺货”页的“下载CSV模板”不含最后一个可选列“求评价延迟秒”（共 21 列）；需要该列时在表头末尾手动添加。
- 表格第一行之后完全为空的行会被跳过；预检结果里的“行号”按“表头为第 1 行、之后每个非空数据行依次加 1”计算，空行不占行号，可能与表格软件里显示的行号不一致。
- 扩展名为 `.xlsx` 时按 XLSX 解析，**只接受恰好一个工作表**（多个或隐藏工作表都会被拒绝）；`.csv`、`.tsv` 按对应分隔符解析，其他扩展名按 CSV 处理；旧版 `.xls` 不支持，请另存为 `.xlsx` 或 CSV。

### 2.2 字段填写规则

#### 基础字段

| 列 | 必填 | 格式 / 取值 | 示例 |
|---|---|---|---|
| 账号ID | 是* | 闲鱼账号 ID（数字字符串）。*可留空，留空时使用上传页必选的“默认发布账号” | `2222660684687` |
| 标题 | 是 | 文本，非空 | `会员组合包自动发货` |
| 描述 | 否 | 文本。留空时默认等于标题 | `下单后发送主卡和附赠卡。` |
| 价格 | 是 | 数字，单位元，最多两位小数（可带 `¥`/`￥` 前缀），必须 > 0 | `19.90` |
| 原价 | 否 | 数字，单位元，最多两位小数，划线价；填写时必须 > 0，否则报“原价格式错误” | `29.90` |
| 库存 | 否 | 整数，> 0，默认 1。留空或无法识别为数字时按 1 处理（带小数时取整数部分）；写 `0` 或负数会报错 | `10` |
| 邮费模式 | 否 | `free`（包邮，默认）、`distance`（按距离计费）、`fixed`（固定邮费）或 `none`（无需邮寄）。也接受 `包邮` / `按距离计费` / `固定邮费` / `一口价邮费` / `无需邮寄` / `不需要邮寄`（不区分大小写），以及 `free_shipping` / `distance_fee` / `no_shipping` | `free` |
| 邮费 | 条件必填 | 数字，最多两位小数。邮费模式为 `fixed` 时必须按实际邮费填写，不能为负；预检只校验格式和不能为负，留空会按 0 元处理，请勿留空。其他模式忽略此列 | `8.00` |
| 图片 | 是 | 1–9 张，多个用 `;`（也接受全角 `；` 或换行）分隔。每项是公网 URL 或图片包内相对路径 | `images/bundle-1.jpg;images/bundle-2.jpg` |

#### 指定类目字段（可选的逐行默认类目）

| 列 | 何时填写 | 格式 / 取值 |
|---|---|---|
| 类目ID | 当前行需要指定默认类目时 | 闲鱼商品类目 ID；必须和“类目名称、频道类目ID”同时填写（四列中任一列有值，三项就都必填） |
| 类目名称 | 填写了“类目ID”时 | 与类目 ID 对应的准确名称 |
| 频道类目ID | 填写了“类目ID”时 | 必须填写闲鱼推荐响应中的准确频道类目 ID |
| 淘宝类目ID | 闲鱼响应有值时 | 按原样填写；“电子资料”没有该值，保持为空 |

上传页面的默认类目可以留空。需要整批固定类目时，选择发布账号后输入关键词，由闲鱼推荐接口返回并保存完整类目信息。系统对每行按以下顺序处理：

1. 当前行填写了完整类目字段时，优先使用当前行类目。
2. 否则，上传页已通过关键词选择默认类目时，使用页面默认类目。
3. 前两项均为空时，调用闲鱼接口，根据标题、描述和图片自动识别。
4. 闲鱼明确没有识别结果时，最终使用“电子资料”（类目 ID `50023914`、频道类目 ID `202036301`）。

因此，表格和上传页都不指定类目时，系统会先自动识别，并只在没有匹配结果时使用“电子资料”。接口超时、鉴权失败和风控错误不会被最终兜底掩盖。

#### 自动化字段（可选，不填或填"否"表示不启用）

启用值接受：`1` / `true` / `yes` / `y` / `on` / `是` / `开启` / `启用`（不区分大小写、忽略首尾空白）。
不启用填：`0` / `false` / `no` / `否` / 留空；其他任何内容都按“不启用”处理。未启用时，对应的内容列会被忽略。

| 列 | 何时必填 | 格式 |
|---|---|---|
| 付款发货启用 | 否 | 启用值 |
| 付款发货内容 | 启用时必填 | 卡密组配置或发货模板动作，见 §3 |
| 评价赠品启用 | 否 | 启用值 |
| 评价赠品内容 | 启用时必填 | 卡密组配置或发货模板动作，见 §3 |
| 变量.<变量名> | 使用的发货模板含 `{{custom.<变量名>}}` 时必填 | 文本，本行取值（如网盘链接），见 §3.1 |
| 模板卡密.<变量名> | 使用的发货模板含 `{{cards.<变量名>}}` 时必填 | `卡密组ID:每件份数`，见 §3.1 |
| 求评价启用 | 否 | 启用值 |
| 求评价等待小时 | 否 | 整数，> 0，默认 72（留空或无法识别为数字时按 72 处理）。发货后多少小时未评价才提醒 |
| 求评价文案 | 启用时必填 | 文本，提醒消息内容 |
| 求评价最多次数 | 否 | 整数，> 0，默认 1（留空或无法识别为数字时按 1 处理） |
| 求评价延迟秒 | 否 | 整数，≥ 0，默认 0（留空或无法识别为数字时按 0 处理）；达到提醒条件后发送前等待的秒数。预检不校验该列的范围，请自行保证不为负 |

发布成功后，系统会为该商品按启用项创建规则：付款后自动发货（发货动作之后固定追加“确认发货”动作）、评价后发送赠品、超时未评价求评价；规则创建发生在商品发布成功之后。

## 3. 卡密组配置格式

"付款发货内容"和"评价赠品内容"两列使用统一格式：

```
卡密组ID:每件份数:延迟秒;卡密组ID:每件份数:延迟秒
```

**规则：**
- 多条之间用 `;`（分号，也接受全角 `；` 或换行）分隔；各段之间用 `:`（也接受全角 `：`）分隔，每条最多 3 段。
- `卡密组ID` 必须是大于 0 的整数。
- `每件份数` 可省略，默认 `1`；必须是大于 0 的整数。
- `延迟秒` 可省略，默认 `0`；必须是 0 到 3600 之间的整数。
- 卡密组 ID 必须是上传者已在"卡密库存"中创建好的组 ID（你准备资料时如果不知道 ID，留空并在交付说明里标注"需运营填卡密组 ID"）。

**示例：**

| 内容列填法 | 含义 |
|---|---|
| `101:1` | 从卡密组 101 发 1 份 |
| `101:1;102:2` | 卡密组 101 发 1 份 + 卡密组 102 发 2 份 |
| `101:1:0;102:2:30` | 卡密组 101 立即发 1 份；卡密组 102 延迟 30 秒后发 2 份 |

### 3.1 发货模板动作与逐行变量（每个商品发不同链接）

适用于网盘资源等“每个商品内容不同、发货话术相同”的场景：建一个共享的发货模板，每行只填本商品的取值，导入时**不会新建卡密组或模板**。

1. 先在“发货模板”中建好模板，例如消息 `资源：{{custom.link}} 提取码：{{custom.code}}`，记下模板 ID。
2. “付款发货内容”或“评价赠品内容”写模板动作 `T模板ID`（也可写 `模板模板ID`，`T` 不区分大小写），可选延迟秒 `T模板ID:延迟秒`；可与卡密动作用 `;` 混写，按书写顺序执行，例如 `101:1;T12:30`。
3. 模板里每个 `{{custom.<变量名>}}` 对应一列，表头为 `变量.<变量名>`（也接受 `模板变量.<变量名>`、`custom.<变量名>`），单元格填本行取值，可包含 `:`、`;` 和完整 URL。
4. 模板里每个 `{{cards.<变量名>}}` 对应一列，表头为 `模板卡密.<变量名>`，单元格填 `卡密组ID:每件份数`（份数省略为 1）。

**规则：**
- 变量名只能包含字母、数字、下划线和短横线，与模板变量写法一致。
- 同一行的变量列供该行所有模板动作共用；每个模板只取自己用到的变量，模板没用到的列会被忽略。
- 模板必须属于上传者且已启用；模板用到的每个自定义变量都必须填写非空值，用到的每个卡密变量都必须绑定一个已启用的文本、批量数据或已配置的 API 卡密组。任何一项不满足，预检就会把该行标为不通过，并提示“缺少模板变量 xxx”“缺少模板卡密 xxx”等（提示只含变量名，不含取值）。
- 不含 `变量.`、`模板卡密.` 列且不使用 `T` 动作的旧表格，解析和预检结果与之前完全相同。

**示例：**

| 付款发货内容 | 变量.link | 变量.code | 模板卡密.main | 含义 |
|---|---|---|---|---|
| `T12` | `https://pan.example.com/s/abc` | `x7k2` | | 发送模板 12，填入本行链接和提取码 |
| `T12:30` | `https://pan.example.com/s/def` | `m9q1` | | 等待 30 秒后发送模板 12 |
| `101:1;T13` | `https://pan.example.com/s/ghi` | | `102:1` | 先发卡密组 101，再发模板 13（其 `{{cards.main}}` 取卡密组 102） |

## 4. 图片规格

每个商品必须 1–9 张图片。两种方式二选一（可混用）：

### 4.1 用公网 URL（推荐，无需图片包）

直接在"图片"列填图片直链，多个用 `;` 分隔：

```
https://cdn.example.com/bundle-1.jpg;https://cdn.example.com/bundle-2.jpg
```

要求：`http(s)://` 开头，可公开访问，图片格式。预检只检查是否以 `http://` 或 `https://` 开头，不会下载；真正下载发生在发布该行时：按默认出站策略必须解析到公网地址（本机和内网地址默认被拒绝），单张不超过 10 MiB，且内容必须是图片，否则该行发布失败。

### 4.2 用本地图片（需交付图片包 ZIP）

把所有图片打成一个 `.zip`，表格"图片"列填**相对 ZIP 根的路径**。

**ZIP 结构示例：**
```
images.zip
├── bundle-1.jpg
├── bundle-2.jpg
└── sub/
    └── product.jpg
```

**表格"图片"列对应填法：**
```
bundle-1.jpg;bundle-2.jpg
sub/product.jpg
```

**图片限制：**
- 单张图片最大 10 MiB，超过会使整个 ZIP 被拒绝。
- 仅保留 `image/*` 类型（jpg / png / webp 等），其他文件和空文件自动忽略。
- 整个 ZIP 最大 200 MiB；ZIP 内文件数最多 500 个，解压后图片总大小最多 500 MiB。
- 路径分隔符用正斜杠 `/`（系统会把反斜杠转换为 `/`，但仍建议统一使用 `/`）。
- 路径不要以 `/` 开头，不要包含 `..`。
- 预检会检查本地路径在 ZIP 解压目录中存在且是文件，路径写错的行会被标记为“需修正”。

## 5. 资料包必须通过的校验

资料包上传后系统会逐行预检。**你交付前请按下表自检每一行**，任一项不通过该行会被标记无效（不会上架）：

| 检查项 | 规则 |
|---|---|
| 账号ID | 非空（或上传者用默认账号），且必须是上传者已授权的账号 |
| 标题 | 非空 |
| 价格 | > 0 |
| 库存 | > 0（默认 1） |
| 邮费模式 | `free` / `distance` / `fixed` / `none`（或 `包邮` / `按距离计费` / `固定邮费` / `无需邮寄` 等别名，见 §2.2） |
| 邮费 | 邮费模式为 `fixed` 时格式合法（最多两位小数）且 ≥ 0；预检不会因留空报错，但留空按 0 元提交，请务必填写 |
| 图片 | 1–9 张；本地路径必须在 ZIP 内存在；URL 必须以 `http://` 或 `https://` 开头 |
| 指定类目 | 当前行填写了任一类目字段时，“类目ID、类目名称、频道类目ID”必须同时存在；页面默认类目可为空 |
| 付款发货 | 启用时：内容列必填至少一条卡密组或模板动作；卡密格式须为 `卡密组ID:每件份数:延迟秒`，模板格式须为 `T模板ID:延迟秒`；卡密组 ID 必须属于上传者；每件份数 > 0；延迟秒在 0–3600 之间；模板须已启用，其自定义变量全部有非空的 `变量.*` 列取值，卡密变量全部由 `模板卡密.*` 列绑定到可用卡密组（见 §3.1） |
| 评价赠品 | 同上 |
| 求评价 | 启用时：等待小时 > 0、文案非空、最多次数 > 0；延迟秒应 ≥ 0（预检不校验） |

## 6. 硬性限制

| 限制项 | 上限 |
|---|---|
| 单个资料包商品行数 | 50 条（空行不计） |
| 表格文件大小 | 20 MiB |
| 图片 ZIP 大小 | 200 MiB |
| ZIP 内文件数 | 500 个 |
| ZIP 解压后图片总大小 | 500 MiB |
| 单张图片大小 | 10 MiB |
| 单个商品图片数 | 9 张 |
| 单次上传请求总大小 | 224 MiB |
| 商品发布强制间隔（上传页设置） | 1–3600 秒，默认 5 秒 |

> 超过 50 条请拆成多个资料包分别交付。预检未通过的行（“需修正”）不会发布，也不会被“重试失败项”重试；修正表格后需重新上传预检。

## 7. 完整示例

### 7.1 仅发布商品、不绑自动化（最简）

无需图片包（用的是 URL）。四个逐行类目列可留空；页面默认类目也留空时，系统会自动识别。

## 8. 交付前自检清单

逐项确认后再交付：

- [ ] 表格第一行是表头，且和 §2.1 一致（中或英，不混用；别名见 §2.1）
- [ ] 每行都有账号ID（或确认上传者会用默认账号）
- [ ] 每行标题非空、价格 > 0、库存 > 0
- [ ] 邮费模式只填 `free` / `distance` / `fixed` / `none`（或对应中文名）；`fixed` 时邮费已填且不为负
- [ ] 每行图片 1–9 张，多个用 `;` 分隔
- [ ] 需要整批固定类目时，已在上传页通过关键词获取默认类目；否则保持为空
- [ ] 需要逐行指定类目时，“类目ID、类目名称、频道类目ID”同时填写；淘宝类目 ID 按接口响应填写
- [ ] 用本地路径的图片，在 ZIP 内对应路径都能找到
- [ ] 用 URL 的图片，链接是 `http(s)://` 且可公开访问
- [ ] 启用了付款发货/评价赠品的行，内容列按 §3 格式填写，卡密组 ID 已知（或已标注需运营补填），延迟秒在 0–3600 之间
- [ ] 使用 `T模板ID` 的行，模板用到的每个 `{{custom.*}}` 都有对应 `变量.*` 列且本行已填写，每个 `{{cards.*}}` 都有对应 `模板卡密.*` 列
- [ ] 启用了求评价的行，等待小时 > 0、文案非空、最多次数 > 0
- [ ] 如填写求评价延迟秒，数值为大于等于 0 的整数；留空时使用 0（预检不校验此列）
- [ ] 总行数 ≤ 50；超过请拆包
- [ ] 表格文件 ≤ 20 MiB；图片 ZIP ≤ 200 MiB（文件数 ≤ 500）；单图 ≤ 10 MiB
- [ ] `.xlsx` 只含一个工作表
- [ ] CSV 用 UTF-8 编码（建议带 BOM，Excel 打开不乱码）

满足以上，资料包即可直接上传，预检会全部通过。
