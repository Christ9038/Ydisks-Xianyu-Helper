# 全函数与全变量中文注释规范

## 1. 适用范围

本规范适用于仓库中的 Go、TypeScript 和 TSX 生产代码与测试代码。
生成代码、第三方代码、`internal/webui/static` 构建产物和数据文件不在手工注释范围内。

所有新增或修改的声明必须立即满足本规范。历史代码通过注释检查基线渐进清理；
每个重构阶段必须清除其负责文件内的历史注释债务，最终删除全部基线豁免。

## 2. 注释质量原则

注释必须至少解释下列一项实际信息：

- 业务职责或业务含义；
- 输入、输出和错误语义；
- 数据单位、格式、取值范围或默认值；
- 生命周期、所有权、取消和释放责任；
- 并发保护、锁顺序或 goroutine 责任；
- 敏感数据的用途和禁止传播范围；
- 兼容来源、删除条件或外部协议约束；
- 采用某种实现而非直观实现的原因。

禁止只把标识符翻译成中文或复述语法。例如“err 表示错误”“count 表示数量”不合格；
应说明是什么操作的错误、统计什么对象、单位是什么以及如何使用。

修改代码语义时必须同步更新相关注释。错误注释视为缺陷，不得以“已有注释”为由保留。

## 3. Go 规范

### 3.1 Package、类型和函数

- 每个 package 必须有唯一 package 注释；
- 每个导出和未导出类型必须有中文注释；
- 每个函数和方法必须有中文注释；
- 导出标识符注释遵循 Go 文档约定，以标识符名称或可读主语开头；
- 函数注释必须解释所有参数、返回值、主要副作用和错误语义；
- 方法注释应说明 receiver 所代表对象以及是否可并发调用；
- 匿名函数必须由变量注释或紧邻注释说明用途和回调参数。

### 3.2 变量与常量

以下声明必须有准确中文注释：

- package 级 `var` 与 `const`；
- const block 中的每个语义不同成员；
- 结构体字段；
- 接口方法及参数；
- 函数参数和命名返回值；
- 局部 `var`；
- `:=` 短变量声明；
- `for`/`range` 的索引和值变量；
- type switch、类型断言和 map 查询中的 `ok`；
- 闭包捕获的状态变量；
- 锁、Context、CancelFunc、WaitGroup、channel 和 timer。

同一条声明可以由一条注释分别解释全部变量：

```go
// account 保存已通过所有权校验的账号摘要；queryErr 保存读取摘要时产生的数据库错误。
account, queryErr := repository.GetSummary(ctx, accountID)
```

循环变量必须说明当前遍历对象：

```go
// rowIndex 表示导入文件中的数据行下标；row 保存当前待验证的订单数据。
for rowIndex, row := range rows {
	// ...
}
```

### 3.3 并发注释

包含锁或 goroutine 的类型和函数必须明确：

- 锁保护哪些字段；
- 是否允许持锁调用外部 I/O；
- 多个锁的获取顺序；
- goroutine 由谁启动、取消和等待；
- channel 的发送者、接收者和关闭者；
- Context 的来源和取消责任；
- Stop/Close 是否幂等。

### 3.4 敏感数据注释

Cookie、Token、密码、SMTP 凭证和远程滑块秘密必须标明：

- 值是否为明文；
- 允许存在的最小作用域；
- 是否允许日志记录或 JSON 序列化；
- 由谁负责加密、解密和更新。

## 4. TypeScript 与 TSX 规范

### 4.1 函数和组件

- React 组件使用中文 JSDoc 说明页面或组件职责；
- Hook 必须说明拥有的状态、执行的副作用、取消方式和返回值；
- 事件处理器必须说明由什么用户操作触发以及成功后的状态变化；
- 数据转换函数必须说明输入 DTO、输出 UI model 和兼容逻辑；
- 回调函数的参数必须由紧邻注释解释；
- `useEffect` 必须说明同步的外部系统和 cleanup 责任，不能只写“初始化”。

### 4.2 变量和状态

以下声明必须有准确中文注释：

- module 级 `const`/`let`；
- 组件和函数内的 `const`/`let`；
- `useState` 的状态值和 setter；
- `useRef` 保存的临时值、DOM 或生命周期标记；
- `useMemo` 的派生值及其昂贵原因；
- `useCallback` 的用途；
- 解构变量；
- `map`、`filter`、`reduce` 等回调参数；
- `catch` 错误变量；
- 表单、请求、分页、轮询和 generation 状态。

同一条 Hook 声明可以共用一条注释：

```tsx
/** accounts 保存账号摘要；setAccounts 只在当前请求仍为最新请求时替换列表。 */
const [accounts, setAccounts] = useState<AccountSummary[]>([]);
```

### 4.3 React 注释必须包含的特殊信息

- 异步请求是否可以取消；
- 晚到响应如何防止覆盖新状态；
- state 是服务端数据、表单数据还是短暂 UI 状态；
- derived value 为什么需要或不需要 memo；
- effect 的依赖和 cleanup 是否完整；
- 敏感字段是否会进入浏览器状态。

## 5. 自动检查与人工审查

自动检查负责：

- 声明附近是否存在注释；
- 注释是否包含中文；
- 新增声明是否被历史基线错误豁免。

导出 Go 标识符的 doc comment 起始词、参数语义和并发/敏感数据说明由人工审查负责，后续可在不放宽中文门禁的前提下增加静态规则。

人工审查负责：

- 注释是否准确；
- 是否解释实际语义而不是复述代码；
- 并发、敏感性和兼容条件是否完整；
- 代码变化后注释是否仍然成立。

PR 描述必须声明本次清理了哪些文件的注释基线，并列出仍保留的历史范围。

## 6. 禁止做法

- 禁止为了通过检查批量生成“变量 X 保存 X”一类注释；
- 禁止用英文占位注释替代中文解释；
- 禁止注释掉旧代码而不删除；
- 禁止使用注释掩盖过长函数或错误抽象；
- 禁止因补注释顺手修改无关行为；
- 禁止修改生成文件来满足手工注释检查；
- 禁止让注释泄露密码、Cookie、Token 或真实生产数据。
