# API 兼容边界清单

本文档记录 HTTP API 版本化迁移后的兼容边界，避免在没有证据时删除仍可能被外部客户端使用的旧入口。

## 当前规则

- 前端生产 API 适配层只能调用 `/api/v1/...`；该规则由 `frontend/featureArchitecture.test.ts` 校验。
- 服务端旧入口继续作为兼容适配层保留，必须复用同一个 handler、鉴权和 DTO，不得复制业务逻辑。
- 新增接口必须先进入 `/api/v1/...`，旧路径只有在确认外部调用方为零后才允许删除。
- 删除旧路径前必须在本文件记录调用方审计证据、迁移版本和回滚方式，并同步删除对应契约测试。

## 阶段 3 调用方审计

旧入口的仓库内调用方由 `tools/architecturecheck` 中的
`TestFrontendProductionRequestsUseVersionedAPI` 静态清点，并在每次改动前端请求适配层时运行：

| 调用方范围 | 当前证据 | 结论与删除条件 |
| --- | --- | --- |
| React 生产源码（`frontend/**/*.ts`、`frontend/**/*.tsx`，排除测试和构建产物） | 静态扫描未发现未版本化业务请求 | 已迁移到 `/api/v1`；新增调用必须继续通过该门禁 |
| React 测试、文档和兼容适配器 | 不作为生产调用方计数 | 可以保留历史样例，但不得被打包到生产请求路径 |
| 服务端旧路由 | 各领域版本化契约测试同时请求新旧入口 | 旧路径继续由同一 handler 提供；删除前必须确认外部调用方为零并同步删除契约测试 |
| 桌面包、脚本和第三方客户端 | 仓库内无法观测 | 暂不删除；发布侧需要增加请求遥测，连续两个发布周期无调用后才设置 Sunset 版本，并保留回滚版本 |

该清点只证明仓库内 React 生产请求已经迁移，不能推断外部调用方为零。删除旧路径前，发布说明必须
记录调用方审计、Deprecation/Sunset 版本、观测窗口和回滚方式；在证据缺失时保持兼容入口。

## 受控动态键响应

以下动态响应是已有客户端依赖的动态键 JSON 形状，本阶段不改变字段形状。它们的值类型仍是具名
DTO 或明确标量；架构门禁只允许这类已登记的兼容结构，禁止新增 `map[string]any`、
`[]map[string]any` 或未登记的动态响应类型。所有保留项统一通过历史 API 遥测观察，并计划在
`v2.0` 评估退场：

| 响应类型 | 动态键语义 | Sunset | 删除条件 |
| --- | --- | --- | --- |
| `settingsResponse` | 非敏感系统设置键 | `v2.0` | 连续两个发布周期外部调用为零，完成前端与桌面包回归 |
| `notificationBindingListResponse` | 按账号 ID 分组的绑定列表 | `v2.0` | 连续两个发布周期外部调用为零，保留版本化回滚 |
| `automationRulePageResponse` | `trigger_counts` 按触发类型统计 | `v2.0` | 连续两个发布周期外部调用为零，完成契约测试迁移 |

## 仍保留的旧入口

服务端目前保留 `/api/...`、`/...` 和 `/admin/...` 等历史入口。仓库内生产 React 调用已经全部迁移到 `/api/v1/...`，服务端契约测试仍覆盖新旧路径的等价响应和权限边界。

这些旧入口暂不删除，因为它们可能被已部署的桌面包、脚本或第三方客户端调用。后续发布周期收集到外部调用方为零的证据后，再按“一个资源域一个 PR”逐步删除，并保留版本化入口回归测试。
